# 项目配置与模块

一个项目从一个 `.sbdsl` 文件开始，通过 `import` 引入其他文件，最后生成一个 `.sb3`。`sbdsl.buildsb` 保存入口、输出、扩展和舞台资源；角色的初始位置、造型等写在源码的 [`@init`](./sprites.md) 中。

## sbdsl.buildsb

一般只需要入口和输出路径：

```sbdsl-build
entry: "./src/main.sbdsl"
output: "./dist/project.sb3"
```

`sbdsl.buildsb` 是 ScratchDSL 的构建配置。字段写成 `字段名: 值`，字段之间换行，也可以用逗号分隔。末尾允许逗号；最外层的 `{}` 可以省略，内部对象仍要保留。

字段名使用 ASCII 字母、数字和下划线，首字符不能是数字。名称、路径、枚举等字符串值仍用双引号；数字和布尔值直接写。数组元素也可用换行或逗号分隔，并允许尾逗号。配置支持[源码中的 `#` 注释](syntax.md#空白与注释)。字符串和数字使用 JSON 字面量规则，具体转义见[初始化数据](sprites.md#角色初始状态)。重复字段和未知字段都会报错。

其他字段按需要添加，不必把默认值再写一遍：

| 字段 | 用途 | 省略时 |
| --- | --- | --- |
| `entry` | 唯一的 `.sbdsl` 入口路径，不能是数组 | 构建配置时必填；CLI 直接指定源码时使用该源码 |
| `output` | 生成的 `.sb3` 路径 | 入口同目录下同名的 `.sb3` |
| `name` | 项目名称 | 不指定名称 |
| `srcDir` | 导入模块时的第二查找目录 | 配置目录下的 `src` |
| `extensions` | 本地扩展 `.js` 路径数组，每项可用 `as "别名"` 指定命名空间 | `[]` |
| `stage` | 舞台的 `backdrops` 和 `sounds` | 默认空白背景，无声音 |
| `runtime` | TurboWarp 运行设置 | 不写入运行设置 |

例如，加入扩展、背景和帧率设置：

```sbdsl-build
entry: "./src/main.sbdsl"
output: "./dist/project.sb3"
extensions: ["./extensions/自定义拓展.js"]

stage: {
    backdrops: [
        {
            name: "背景1"
            path: "./assets/bg.svg"
        }
    ]
}

runtime: {
    fps: 60
}
```

`stage.backdrops` 和 `stage.sounds` 的元素使用[资源字段](sprites.md#角色初始状态)，分别对应造型和声音；舞台没有 `@init`。`runtime` 可包含 `fps`、`stageWidth`、`stageHeight`、`maxClones`、`fencing`、`miscLimits`、`hqPen`，每项都可省略。它们作为 `_twconfig_` JSON 注释写入 Stage，供 TurboWarp 读取，详见[运行设置](sb3.md#turbowarp-运行时设置)。

配置不接受角色初始化字段，`sprites` 与其他未知字段一样报错。角色名直接取 `@sprite "角色名"`；造型和声音对象中的 `name` 则是资源名称。

`extensions` 只接受本地 `.js` 路径，不接受 `http:`、`https:`、`file:`、`data:` 等 URL。Windows 盘符路径仍是本地路径。每项可以在路径后写 `as "别名"`：

```sbdsl-build
extensions: [
    "./extensions/自定义拓展.js" as "tools"
]
```

扩展对所有源文件可见。上例使用 `tools.[...]` 调用；不写 `as` 时使用文件名命名空间，如 `自定义拓展.[...]`。`as` 只用于根 `extensions` 数组，别名替换默认名字，具体规则见[扩展](./extensions.md)。

## 配置查找与路径

CLI 按以下方式选取配置：

| 构建输入 | 使用的配置 |
| --- | --- |
| 不传输入 | 当前工作目录的 `sbdsl.buildsb` |
| 配置文件路径 | 指定文件 |
| `.sbdsl` 路径 | 从源码所在目录向上查找最近的 `sbdsl.buildsb`，并将 `entry` 替换成指定源码 |
| `.sbdsl` 路径，未找到配置 | 使用默认配置，扩展为空、舞台使用默认资源，角色仍读取源码中的 `@init` |

相对路径的基准如下；本地绝对路径直接使用，资源路径也不接受 URL。

| 路径 | 相对目录 |
| --- | --- |
| CLI 输入、`-o` | 当前工作目录 |
| 配置中的 `entry`、`srcDir`、`output`、`extensions` | 配置文件目录 |
| 配置中的舞台背景、声音 | 配置文件目录 |
| 角色 `@init` 中的造型、声音 | 声明该 `@init` 的 `.sbdsl` 文件目录，即使该文件被其他文件导入 |

`srcDir` 省略时取配置文件目录下的 `src`；没有配置文件则取入口源码目录。输出路径优先使用 CLI 的 `-o`，其次是配置的 `output`，都未指定时使用入口源码同目录、同名的 `.sb3`。直接构建源码时只替换配置的 `entry`，其他设置仍保留，显式 CLI 参数按上述优先级处理。

## import

```scratch
import entities
import utils.math
```

导入名不带 `.sbdsl` 后缀，点号转换成目录分隔符。`import utils.math` 先查找当前文件目录下的 `utils/math.sbdsl`，再查找 `srcDir` 下的同一路径，使用第一个存在的文件；都不存在时报错。

导入只允许放在文件顶层或顶层 `@stage` 内，可穿插在其他声明之间。角色、事件、自制积木和控制流体中不能导入文件。

文件按规范化绝对路径去重：消除 `.`、`..`，解析符号链接，并遵循所在文件系统的大小写规则。用路径别名导入同一文件不会重复加载。

## 展开顺序

编译器进入文件时就将其加入已访问集合，入口文件也一样。随后按源码顺序处理条目，遇到 `import` 就在当前位置深度优先展开目标文件，再继续处理当前文件。已经访问过的文件直接跳过，循环导入也按此处理。

例如入口依次导入 A、B，而 A 在自己的声明之前导入 B，那么先处理 B，再处理 A 的后续声明；入口稍后导入 B 时跳过。

`@stage { ... }` 在出现位置展开，不建立作用域。其中允许导入、角色、变量、列表、公共自制积木和舞台事件，但不能再嵌套 `@stage`。展开后的条目与直接写在该位置相同。

这个顺序决定声明覆盖、角色创建和追加检查、过程重复检查及输出排列，不决定多个事件脚本的运行先后。

## 声明覆盖

顶层的 `@var`、`@list` 属于 Stage 全局作用域；角色中的声明属于该角色，带 `@global` 的声明仍归入 Stage。同一作用域内同名变量以后一次声明的初始值为准，同名列表则替换整个初始数组，不拼接。最终只保留一个条目，所有引用都指向它。

```scratch
# A.sbdsl
@var score = 1
```

```scratch
# B.sbdsl
@var score = 2
```

```scratch
# main.sbdsl
import A
import B
```

这里的全局 `score` 初值为 `2`，交换导入顺序后为 `1`。覆盖只决定构建时的初值，运行后的值由脚本决定。

所有声明合并后再绑定引用，因此可以引用同一作用域稍后声明的变量、列表和过程。数据初值的写法、私有与全局引用的查找规则见[变量和列表](sprites.md#变量和列表)。

## 创建和追加角色

项目内角色名不能重复，跨文件补充同一个角色的逻辑要使用 `add`：

```scratch
import entities

@sprite "玩家" add {
    当按下 /'space'/ 键 {
        [说 "释放技能"]
    }
}
```

这里要求 `entities` 已经创建“玩家”。处理 `add` 时角色尚不存在就报错，后面的定义不能补救。追加体不能写 `@init`，也不能修改角色初始状态或资源。

只包含追加块的文件若要独立构建，需要先导入创建角色的文件。创建体和追加体允许的声明见[角色语法](sprites.md#声明可以写在哪里)。

## 自制积木和事件的导入

导入文件的公共自制积木会加入全局作用域，角色私有自制积木仍归属原角色。同一作用域的签名重复时报错。公共过程按定义处绑定引用，不随调用角色改变；详见[自制积木](sprites.md#自制积木)。

每个 `.sbdsl` 文件都可以包含舞台和角色，也可以作为入口。构建只保留入口文件的舞台事件：被导入文件中的裸顶层事件及 `@stage` 内的舞台事件丢弃，角色事件保留。这样模块可以自带舞台测试脚本，导入时不会运行它们。

被丢弃的舞台事件仍要通过词法、括号和条目结构检查，但不做引用绑定、公共过程可达性分析，也不创建隐式变量。
