# VS Code 插件

支持本地 Windows x64，要求 VS Code 1.91 或更新版本。

## 安装和使用

从 [GitHub Releases](https://github.com/BlueIrisSky/ScratchDSL/releases/latest) 下载 `scratchdsl-0.1.0-win32-x64.vsix`，在扩展视图右上角选择“从 VSIX 安装…”并打开它。随后打开工程文件夹和 `.sbdsl` 文件，语言模式应显示为 ScratchDSL。

构建配置 `*.buildsb` 使用独立的 ScratchDSL Build 语言模式（`sbdsl-build`），支持字段、值和注释高亮。打开配置时，点击编辑器右上角的构建按钮即可使用这份配置编译工程；自动查找配置时只识别默认名称 `sbdsl.buildsb`。

`.sbdsl` 文件带有橙黄色积木图标，构建配置使用独立的橙黄色文件与小锤图标，两者分别适配浅色和深色背景。图标由当前文件图标主题决定；如果没有显示，可切换到 VS Code 自带的 Seti 主题。插件不会自动更换你的图标主题。

输入 `[移` 时可选择移动积木，按 Tab 跳到参数位置。没有弹出候选时按 `Ctrl+Space`。插件自带编译器，不需要全局 `sbdsl`、Rust 或 Node.js，也不修改 PATH。

高亮覆盖积木文字、事件和控制流、变量与列表、参数、自制积木定义、角色名、导入模块和扩展调用，颜色跟随当前 VS Code 主题。比较直接写 `<$hp < 1>`、`<$score > 100>`，外层尖括号标为边界，中间的 `<`、`>` 标为运算符。菜单使用 `/'选项'/`，两侧分隔符和内容分别高亮。

`@init` 识别裸字段名、字符串、数字和 `#` 注释。输入时自动补齐双引号、圆括号、方括号和花括号。`/`、`<` 容易与菜单或运算符混淆，因此不自动补齐；`#` 兼作行注释与块注释，也没有绑定通用的“切换行注释”操作。

## 补全

| 输入位置 | 候选 |
| --- | --- |
| `[移` 等积木开头 | 内置积木、已加载的扩展积木、可见的自制积木 |
| `$` | 变量、列表和全局引用前缀 |
| `$list:` | 列表 |
| `$global:`、`$global:list:` | 全局变量、全局列表 |
| 自制积木体内的 `@`、`<@` | 当前过程的普通参数、布尔参数 |
| `@init` 内 | 属性名和枚举值 |
| `*.buildsb` 内 | 当前对象的属性名和布尔值，包括 `runtime`、`stage` 与资源对象 |

变量和列表候选来自 `@var`、`@list` 声明，包含入口及其导入模块中的未保存内容。角色内优先使用私有数据，显式全局前缀可以访问同名的全局数据。其他角色的私有数据和自制积木不会出现在候选中；公共自制积木的内部仍按全局作用域补全。

选中自制积木后，按 Tab 依次填写参数。变量、列表和参数补全只替换当前引用，保留后面的文字和参数；名称含空格等字符时自动加引号。能判断当前是舞台还是角色时，也会过滤不适用的内置积木。注释、普通字符串和菜单内容中不提供积木候选，带引号的符号名称可以补全。

## 检查和构建

错误提示会使用尚未保存的 `.sbdsl` 和 `*.buildsb` 内容，其余文件从磁盘读取。模块有文件路径但还没保存时，也可以被导入。修改源码、配置或本地扩展后会重新分析，关闭文件后恢复读取磁盘版本。

打开配置时，分析使用这份配置的 `entry`；打开源码时，使用向上找到的最近 `sbdsl.buildsb` 的 `entry`，打开被导入模块不会改变入口。没有配置时分析当前源码。未命名文件只能检查局部语法和提供补全，构建前需要保存。

命令面板中可以执行：

| 命令 | 作用 |
| --- | --- |
| `ScratchDSL: 构建工程` | 保存相关文件，编译为 `.sb3` |
| `ScratchDSL: 检查工程` | 保存相关文件并完整检查，不输出 `.sb3` |
| `ScratchDSL: 显示输出` | 查看构建结果、错误和日志 |
| `ScratchDSL: 重启语言服务器` | 重新启动语言服务 |

构建与检查在活动文件为 `*.buildsb` 时精确使用该配置，构建按钮也使用其所在编辑器的配置，允许任意文件名。活动文件为源码时，才向上查找最近的默认配置 `sbdsl.buildsb`，使用其中的 `entry`；没有配置时使用活动源码。多根工作区没有活动源码或配置时，会提示选择目录。执行前会保存相关工程文件，包括尚未保存的配置。终端中直接传入 `.sbdsl` 的行为不同，见[入口规则](cli.md#选择入口)。

实时诊断基于工程 AST，检查入口及其导入模块的语法、角色声明、作用域和积木调用，未打开的导入文件也会检查。一次可以显示多处错误；一处写错后，会继续分析能识别的后续声明和语句。错误显示在红色波浪线和“问题”面板中，修复或移除导入后自动更新。造型、音频的完整检查需要运行“检查工程”或“构建工程”。

## 设置和工作区信任

`scratchdsl.serverPath` 留空时使用插件自带的编译器，也可以填入另一份编译器的绝对路径。`scratchdsl.trace.server` 控制协议日志，可选 `off`、`messages`、`verbose`，默认关闭。

本地扩展的 `getInfo()` 需要执行 JavaScript，因此只有信任工作区后才会读取。受限模式仍提供高亮、局部诊断和内置补全，没有第三方扩展的工程也会检查内置积木；配置了扩展但尚未加载时，跳过依赖模板的语义检查。

受限模式也可补全源码中的变量、列表和自制积木；这部分只读取声明，不执行扩展。受限模式不能构建或执行完整检查，工作区设置中的自定义服务器路径也会被忽略。授予信任后语言服务器自动重启；撤销信任时由 VS Code 重新加载窗口。

## 目前的限制

- 不支持 WSL、SSH、容器、浏览器版及其他操作系统。
- 无法确定边界的破损片段会跳过，部分错误的标记范围仍覆盖整个积木。构建配置仍先报告一个错误；未被导入且未打开的源码不参与工程分析。
- 积木模板补全用于调用开头，输入参数后不会替换整条调用；参数中的变量、列表和过程参数仍可单独补全。暂不提供资源路径或独立菜单值的补全，也不执行动态菜单方法。
- 扩展模板同文且无法区分时，补全会插入显式 opcode 调用。列表“包含”的内置模板存在歧义，目前不提供该候选。
- 还没有悬停说明、跳转、引用查找、重命名、格式化、大纲、语义高亮或工程入口选择器。

语言服务器的实现见 [LSP 文档](lsp.md)，制作 VSIX 的步骤见[开发文档](development.md)。
