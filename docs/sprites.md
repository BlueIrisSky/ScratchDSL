# 角色、变量与自制积木

每个 `.sbdsl` 文件都可以作为入口，不需要声明文件身份。文件顶层的事件属于舞台，角色事件写在 `@sprite` 中：

```scratch
@var score = 0

当绿旗被点击 {
    [将 $score 设为 0]
}

@sprite "玩家" {
    @init {}
    @var hp = 100

    当角色被点击 {
        [将 $score 增加 1]
    }
}

@sprite "玩家" add {
    当按下 /'space'/ 键 {
        [说 "跳跃！"]
    }
}
```

`@sprite "玩家" { ... }` 创建角色，同一工程内不能再次创建同名角色，即使写在不同文件也不行。需要补充代码时用 `add`；处理到追加块时角色必须已经存在，否则立即报错，不会自动创建。

## 声明可以写在哪里

文件顶层可以写 `import`、变量和列表声明、公共自制积木、舞台事件、角色创建或追加，以及 `@stage { ... }`。

`@stage` 只是顶层包裹：编译器在原位置去掉这层括号，内部条目仍按顶层规则处理，可以包含 `import` 和 `@sprite`。它只能直接写在文件顶层，不能嵌套另一个 `@stage`。

角色创建体必须以唯一的 `@init` 开始，前面的空白和注释不计。之后可以写私有变量和列表、`@global` 声明、私有自制积木和角色事件。追加体允许相同的成员，但不能写 `@init`。角色体中不能出现 `import`、`@stage` 或另一个 `@sprite`。

事件、自制积木和控制流内部只能写命令调用或控制流，不能声明变量、导入文件或再定义事件。这些代码体也不会创建新的变量作用域。反过来，命令和控制流不能孤立地放在文件顶层或角色声明体中，必须放进脚本。

## 角色初始状态

角色创建时必须写 `@init`，即使全部采用默认值，也要写 `@init {}`。省略、重复或放在其他声明之后都会报错。`@init` 不能直接写在文件顶层、`@stage` 体内、角色追加体或运行脚本里；放在 `@stage` 内的角色创建块仍然需要自己的 `@init`。

角色名只在 `@sprite "角色名"` 中指定，`@init` 不接受角色名称字段。

```scratch
@sprite "玩家" {
    @init {
        y: -20
        rotationStyle: "left-right"
        costumes: [
            {
                name: "站立"
                path: "./assets/hero.svg"
            }
        ]
        sounds: [
            {
                name: "跳跃"
                path: "./assets/jump.wav"
            }
        ]
    }

    当绿旗被点击 {
        [移动 10 步]
    }
}
```

只需写要改变的属性，其他属性使用下面的默认值。例中的资源位于源文件旁的 `assets` 目录。相对路径始终以包含这段 `@init` 的 `.sbdsl` 文件所在目录为基准，即使该文件被其他文件导入，也不会改变。允许本地绝对路径，不接受任何 URL。Windows 路径可以用 `/`，也可以按 JSON 转义把反斜杠写成 `\\`。

| 属性 | 接受的值 | 默认值 |
| --- | --- | --- |
| `x`、`y` | 有限数字 | 都为 `0` |
| `size` | 大于 `0` 的有限数字，单位为百分比 | `100` |
| `direction` | 有限数字，单位为度 | `90` |
| `visible` | 布尔值 `true` 或 `false` | `true` |
| `rotationStyle` | `"all around"`、`"left-right"`、`"don't rotate"` | `"all around"` |
| `costumes` | 按顺序排列的造型对象数组 | `[]`，会生成一个空白 SVG 造型 |
| `sounds` | 按顺序排列的声音对象数组 | `[]` |

造型和声音对象中的 `name` 是资源名，和角色名无关。资源对象接受这些字段：

| 字段 | 造型 | 声音 |
| --- | --- | --- |
| `name` | 必填，非空字符串 | 必填，非空字符串 |
| `path` | 必填，本地 SVG / PNG 路径 | 必填，本地 WAV / MP3 路径 |
| `rotationCenterX` | 有限数字，默认图像宽度的一半 | 不接受 |
| `rotationCenterY` | 有限数字，默认图像高度的一半 | 不接受 |
| `bitmapResolution` | 正整数，默认 `1` | 不接受 |

`name` 和 `path` 都不自动裁剪空白，`path` 也必须是非空字符串。同一角色的造型名必须互不相同，声音名也一样；按完整字符串区分大小写，造型与声音之间可以同名。`costumes` 的第一项是项目加载时显示的造型。

`@init` 和 [`sbdsl.buildsb`](project.md) 使用相同的数据写法，`@init` 必须保留外层 `{}`：

- 字段写成 `字段名: 值`。字段名使用 ASCII 字母、数字和下划线，首字符不能是数字；名称、路径、枚举等字符串值仍用双引号。
- 字段和数组元素之间用换行或逗号分隔，允许尾逗号。重复字段和未知字段会报错，资源对象也一样。
- 数字采用 JSON 写法，可有负号、小数和指数，小数点前必须有整数。`.5`、`+1`、`01`、`NaN`、`Infinity` 不合法，数值还必须能表示为有限值。这里的负号不用加 `*`。
- 字符串支持完整 JSON 转义：`\"`、`\\`、`\/`、`\b`、`\f`、`\n`、`\r`、`\t`、`\uXXXX`，但不能直接跨物理行。字符串内的 `#` 是内容。这与普通 DSL 字符串只支持四种转义不同。
- 字符串外可以用单行、行内块和跨行块 `#` 注释，不能用 `//` 或 `/* ... */`。
- 属性可以省略，但不能写成 `null`。不能引用变量或参数，也不能写积木、运算表达式或扩展调用。`@init` 和后面的同级声明之间仍须换行。

这些数据在编译时写入 `.sb3` 的角色属性和资源表，不生成绿旗脚本。再次点击绿旗不会重新应用 `@init`；每次运行都要重置的位置、变量等，应写在事件中。舞台背景和声音仍在 `sbdsl.buildsb.stage` 中设置，舞台没有 `@init`。

## 变量和列表

```scratch
@var score = 0
@list logs = ["开始", 1]

@sprite "玩家" {
    @init {}
    @var hp = 100
    @global @var level = 1
}
```

顶层 `@var`、`@list` 声明舞台上的全局数据。角色创建或追加体中的同类声明属于该角色；在前面加 `@global`，例如 `@global @list logs = []`，则仍然声明全局数据。

`@var 名称` 的初始值默认为 `0`，也可以用 `= 数值或字符串` 指定。`@list 名称` 默认为空列表，也可以写成 `[值1, 值2, ...]`。列表元素只能是数值或字符串，用逗号分隔，不允许尾逗号。初始值不能引用变量或参数，不能含报告积木、运行时运算或嵌套数组。这里的 `[...]` 是声明数组，不是命令积木。

同一作用域、同一数据种类的重复声明，按工程合并顺序用后一次的完整初始值覆盖前一次，最后只保留一个条目。列表也是整体替换，不会拼接。例如先处理 `@var score = 1`，再处理 `@var score = 2`，最终初始值就是 `2`，即使两条声明在不同文件中。

变量和列表分别命名；全局数据、不同角色的私有数据也分别保存，彼此不会覆盖。

编译器合并工程并收集全部声明后，再解析引用。角色事件和私有自制积木中的普通引用先找该角色的私有数据，再找全局数据；公共自制积木只找全局数据。`$global:名称` 和 `$global:list:名称` 可显式引用全局数据，绕过同名私有数据。

仍然找不到变量时，会在舞台创建初始值为 `0` 的全局变量，显式全局变量引用也一样。列表必须声明，找不到就报错。被导入文件中丢弃的舞台事件不会参与引用查找，也不会因此创建变量。

## 自制积木

定义头由固定文字和参数组成，不另设一个独立的过程名称。`@名称` 声明字符串/数值参数，`<@名称>` 声明布尔参数；同一个自制积木的参数名不能重复。

```scratch
定义自制积木 移动并播报 步数: @steps 是否说话: <@should_say> 内容: @msg @warp {
    [移动 @steps 步]
    如果 <@should_say> 那么 {
        [说 @msg]
    }
}

@sprite "示例角色" {
    @init {}
    当绿旗被点击 {
        [移动并播报 步数: 20 是否说话: <true> 内容: "到达目标点"]
    }
}
```

`@warp` 表示运行时不刷新屏幕，最多写一次，位置必须在所有固定文字和参数之后、过程体 `{` 之前。`warp` 不能作为参数名。

调用时匹配整个积木模板，不按参数名查找。声明签名由规范化的固定文字和槽位类型按顺序组成，不包含参数名，详见[模板匹配](syntax.md#模板如何匹配)。同一作用域出现两个相同签名的定义会报错，并指出两个定义位置，不会像变量一样覆盖。

顶层定义是公共自制积木，舞台和所有角色都能调用。编译器会在实际调用它的目标中生成相应的过程定义。角色创建或追加体中的定义是私有自制积木，只对该角色可见；不同角色可以各自定义相同签名的积木。

同一个角色内，私有定义和公共定义允许同签名。角色事件或私有自制积木直接调用时，优先使用私有定义。但公共自制积木内部的变量、列表和其他过程调用，都按它在顶层定义时的作用域绑定到全局数据、公共过程；即使被某个角色调用，也不会改用该角色的同名私有定义。

## 跨文件合并

导入文件中的全局数据、公共自制积木、角色创建和追加都会保留，角色内部的事件也会保留；导入文件的顶层舞台事件不会带入入口文件。该文件自己作为入口时，才保留自己的舞台事件。每个文件都能作为入口，但只含角色追加、没有引入相应创建块的文件，单独构建仍会因角色不存在而报错。

声明按[模块展开顺序](project.md#展开顺序)合并。这个顺序决定角色何时创建、`add` 是否有效、变量和列表的最终初始值，以及过程声明是否重复；它不保证多个事件脚本的运行先后。
