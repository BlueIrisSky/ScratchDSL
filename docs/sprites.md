# 角色、变量与自制积木

每个 `.sbdsl` 文件都可以作为入口，不需要声明文件身份。文件顶层的事件属于舞台，角色事件写在 `sprite` 中：

```scratch
score = 0

start:
    score = 0

sprite "玩家":
    init:
        pass
    hp = 100

    当角色被点击:
        score += 1

sprite "玩家" add:
    当按下 'space' 键:
        说("跳跃！")
```

`sprite "玩家":` 创建角色，同一工程内不能再次创建同名角色，即使写在不同文件也不行。需要补充代码时用 `add`；处理到追加块时角色必须已经存在，否则立即报错，不会自动创建。

## 声明可以写在哪里

文件顶层可以写 `import`、数据初值赋值、公共自制积木、舞台事件、段积木、角色创建或追加，以及 `stage:` 的缩进体。

`stage` 只是顶层包裹：编译器在原位置展开这一层，内部条目仍按顶层规则处理，可以包含 `import` 和 `sprite`。它只能直接写在文件顶层，不能嵌套另一个 `stage`，缩进回退或文件结束时结束。

角色创建体必须以唯一的 `init` 开始，前面的空白和注释不计。`init` 和 `sprite` 的范围都由缩进确定，缩进回退或文件结束时结束。之后可以写私有数据初值、`global:名称 = 初值`、私有自制积木、角色事件和段积木。追加体允许相同的成员，但不能写 `init`。角色体中不能出现 `import`、`stage` 或另一个 `sprite`。

事件、自制积木、段积木和控制流内部可以写变量赋值、列表重置、命令调用和控制流，不能导入文件或再定义事件。这些代码体也不会创建新的变量作用域。反过来，命令和控制流不能孤立地放在文件顶层或角色声明体中，必须放进脚本或 `piece:` 段积木。

## 角色初始状态

角色创建时必须写 `init`，即使全部采用默认值，也要写 `init:`，在缩进体里写 `pass`。省略、重复、缺少缩进体或放在其他声明之后都会报错。`init` 不能直接写在文件顶层、`stage` 体内、角色追加体或运行脚本里；放在 `stage` 内的角色创建块仍然需要自己的 `init`。

角色名只在 `sprite "角色名"` 中指定，`init` 不接受角色名称字段。

```scratch
sprite "玩家":
    init:
        y: -20
        rotationStyle: "left-right"
        costumes: [
            {
                name: "站立"
                path: "./assets/hero.svg"
            }
        ]
        sounds: [
            {
                name: "跳跃"
                path: "./assets/jump.wav"
            }
        ]

    start:
        移动(10)步
```

只需写要改变的属性，其他属性使用下面的默认值。例中的资源位于源文件旁的 `assets` 目录。相对路径始终以包含这段 `init` 的 `.sbdsl` 文件所在目录为基准，即使该文件被其他文件导入，也不会改变。允许本地绝对路径，不接受任何 URL。Windows 路径可以用 `/`，也可以按 JSON 转义把反斜杠写成 `\\`。

| 属性 | 接受的值 | 默认值 |
| --- | --- | --- |
| `x`、`y` | 有限数字 | 都为 `0` |
| `size` | 大于 `0` 的有限数字，单位为百分比 | `100` |
| `direction` | 有限数字，单位为度 | `90` |
| `visible` | 布尔值 `true` 或 `false` | `true` |
| `rotationStyle` | `"all around"`、`"left-right"`、`"don't rotate"` | `"all around"` |
| `costumes` | 按顺序排列的造型对象数组 | `[]`，会生成一个空白 SVG 造型 |
| `sounds` | 按顺序排列的声音对象数组 | `[]` |

造型和声音对象中的 `name` 是资源名，和角色名无关。资源对象接受这些字段：

| 字段 | 造型 | 声音 |
| --- | --- | --- |
| `name` | 必填，非空字符串 | 必填，非空字符串 |
| `path` | 必填，本地 SVG / PNG 路径 | 必填，本地 WAV / MP3 路径 |
| `rotationCenterX` | 有限数字，默认图像宽度的一半 | 不接受 |
| `rotationCenterY` | 有限数字，默认图像高度的一半 | 不接受 |
| `bitmapResolution` | 正整数，默认 `1` | 不接受 |

`name` 和 `path` 都不自动裁剪空白，`path` 也必须是非空字符串。同一角色的造型名必须互不相同，声音名也一样；按完整字符串区分大小写，造型与声音之间可以同名。`costumes` 的第一项是项目加载时显示的造型。

`init:` 使用缩进包住属性。属性值与 [`sbdsl.buildsb`](project.md) 使用相同的数据写法；资源数组仍使用 `[]`，资源对象仍使用 `{}`：

- 字段写成 `字段名: 值`。字段名使用 ASCII 字母、数字和下划线，首字符不能是数字；名称、路径、枚举等字符串值仍用双引号。
- 字段和数组元素之间用换行或逗号分隔，允许尾逗号。重复字段和未知字段会报错，资源对象也一样。
- 数字采用 JSON 写法，可有负号、小数和指数，小数点前必须有整数。`.5`、`+1`、`01`、`NaN`、`Infinity` 不合法，数值还必须能表示为有限值。这里的负号不用加 `*`。
- 字符串支持完整 JSON 转义：`\"`、`\\`、`\/`、`\b`、`\f`、`\n`、`\r`、`\t`、`\uXXXX`，但不能直接跨物理行。字符串内的 `#` 是内容。这与普通 DSL 字符串只支持四种转义不同。
- 字符串外可以用单行、行内块和跨行块 `#` 注释，不能用 `//` 或 `/* ... */`。
- 属性可以省略，但不能写成 `null`。不能引用变量或参数，也不能写积木、运算表达式或扩展调用。`init` 和后面的同级声明之间仍须换行。

这些数据在编译时写入 `.sb3` 的角色属性和资源表，不生成绿旗脚本。再次点击绿旗不会重新应用 `init`；每次运行都要重置的位置、变量等，应写在事件中。舞台背景和声音仍在 `sbdsl.buildsb.stage` 中设置，舞台没有 `init`。

## 变量和列表

```scratch
score = 0
logs = {"开始", 1}

sprite "玩家":
    init:
        pass
    hp = 100
    global:level = 1
    start:
        hp -= 1
        logs = {"本轮开始"}
        将(hp)加入(logs)
```

不再使用 `var`、`list` 或 `global var` 声明。文件顶层的 `名称 = 初值` 定义全局数据；角色创建或追加体中的同类赋值定义角色私有数据。`global:名称 = 初值` 始终定义全局数据。右侧是数值或字符串时推断为变量，是 `{...}` 时推断为列表；首次赋值确定种类，之后不能互相转换。

定义位置的右侧只接受字面量。列表元素只能是数值或字符串，用逗号分隔，不允许尾逗号、嵌套列表、变量、参数或运行时算式。列表初值按顺序保留，允许重复值。

同一作用域、相同种类的重复初值定义，按模块展开顺序用后一次的完整初值覆盖前一次。列表也是整体替换，不会拼接。全局与角色私有数据之间禁止同名而种类不同；相同种类的私有数据可遮蔽全局数据。不同角色互不可见的私有数据独立检查。

编译器收集初值定义和脚本赋值后再解析引用，数据种类不取决于哪个事件先运行，引用也可以写在赋值之前。角色事件和私有过程中的普通名称先找私有数据，再找全局数据；公共过程只找全局数据。`global:名称` 绕过同种类的私有数据。脚本中新名称仍创建全局数据；已有私有数据的赋值保留其作用域。

数据名只允许普通标识符，不支持空格或引号。普通值槽与变量/列表目标槽都必须有圆括号：`说(score)`、`显示变量(score)`、`将(score)加入(logs)`。赋值和算术语法糖仍写裸名称：`score += 1`、`score = score+1`。字符串内容写 `说("score")`。

事件和过程中的 `logs = {"a", 1}` 在运行时先清空列表，再依次加入字面量元素；`logs = {}` 清空列表。不支持列表复制或非字面量元素。变量与列表互转、把列表放入普通值槽、把变量放入列表槽均报错，并在 IDE 标红。

未定义的变量引用会在舞台创建初值为 `0` 的全局变量；未定义列表会报错。导入时丢弃的舞台事件不会参与引用查找，也不会因此创建变量。

## 自制积木

定义头由固定文字和参数组成，不另设一个独立的过程名称。`@名称` 声明字符串/数值参数，`<@名称>` 声明布尔参数；也可以写成 `(名称)` 和 `<名称>`，含义相同。括号或尖括号中的名称就是参数名；省略名称时按位置自动命名为 `arg1`、`arg2` 等。定义体内的引用仍写 `@名称`。同一个自制积木的参数名不能重复。定义体在缩进回退或文件结束时结束，空定义体写 `pass`。

```scratch
def 移动并播报 步数: @steps 是否说话: <@should_say> 内容: @msg @warp:
    移动(@steps)步
    if <@should_say>:
        说(@msg)

sprite "示例角色":
    init:
        pass
    start:
        移动并播报 步数:(20)是否说话:<true>内容:("到达目标点")
```

`@warp` 表示运行时不刷新屏幕，最多写一次，位置必须在所有固定文字和参数之后、头部末尾的 `:` 之前。`warp` 不能作为参数名。

调用时匹配整个积木模板，不按参数名查找。声明签名由规范化的固定文字和槽位类型按顺序组成，不包含参数名，详见[模板匹配](syntax.md#模板如何匹配)。同一作用域出现两个相同签名的定义会报错，并指出两个定义位置，不会像变量一样覆盖。

顶层定义是公共自制积木，舞台和所有角色都能调用。编译器会在实际调用它的目标中生成相应的过程定义。角色创建或追加体中的定义是私有自制积木，只对该角色可见；不同角色可以各自定义相同签名的积木。

同一个角色内，私有定义和公共定义允许同签名。角色事件或私有自制积木直接调用时，优先使用私有定义。但公共自制积木内部的变量、列表和其他过程调用，都按它在顶层定义时的作用域绑定到全局数据、公共过程；即使被某个角色调用，也不会改用该角色的同名私有定义。

## 跨文件合并

导入文件中的全局数据、公共自制积木、角色创建和追加都会保留，角色内部的事件也会保留；导入文件的顶层舞台事件不会带入入口文件。该文件自己作为入口时，才保留自己的舞台事件。每个文件都能作为入口，但只含角色追加、没有引入相应创建块的文件，单独构建仍会因角色不存在而报错。

声明按[模块展开顺序](project.md#展开顺序)合并。这个顺序决定角色何时创建、`add` 是否有效、变量和列表的最终初始值，以及过程声明是否重复；它不保证多个事件脚本的运行先后。
