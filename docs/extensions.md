# 扩展

在 `sbdsl.buildsb` 中加载本地 `.js` 文件：

```sbdsl-build
entry: "./src/main.sbdsl"
extensions: ["./extensions/自定义拓展.js"]
```

路径相对配置文件目录，也可以使用本地绝对路径。不支持 URL。编译器读取扩展的 `getInfo()` 来确定积木文字、参数、菜单和 opcode，项目中的所有 `.sbdsl` 都能使用这些积木。

可以在路径后加 `as "别名"`，给源码中的调用换一个名字：

```sbdsl-build
extensions: [
    "./extensions/自定义拓展.js" as "tools"
]
```

此时调用写成 `tools.移动(10)步`，原来的 `自定义拓展.` 前缀不再可用。别名只影响源码中的命名空间，不修改文件名、扩展运行时 ID 或 opcode。

`as` 只用于根配置的 `extensions` 数组，不能写在 `init` 或其他字段中。它前后用空白或 `#` 注释分隔，也可以换行。路径和别名都使用双引号字符串；别名不能为空、不能全是空白，也不能包含控制字符。

## 命名空间

没有写 `as` 时，命名空间取配置路径最后一段文件名，去掉末尾 `.js`。文件名必须以 `.js` 结尾，默认命名空间不能为空；大小写、点、横线等字符原样保留，不做 URL 解码。文件名中的点不表示多级命名空间。

| 文件 | 命名空间 | 调用前缀 |
| --- | --- | --- |
| `自定义拓展.js` | `自定义拓展` | `自定义拓展.` |
| `自定义拓展.min.js` | `自定义拓展.min` | `自定义拓展.min.` |
| `自定义拓展-示例.js` | `自定义拓展-示例` | `自定义拓展-示例.` |

名称以 Unicode 字母或 `_` 开头，后面只含字母、十进制数字、`_`、`-`、`.` 时可以直接写，例如 `自定义拓展.`、`自定义拓展.min.`。其他名称用双引号包裹，例如 `"我的 拓展".`；引号内使用[字符串转义](./syntax.md)。裸写与引号写法指向同一个名字，名称区分大小写。

裸写时，最后一个点分开命名空间和积木；名字中的点不表示多级查找。帽子积木固定文字的首段若含点，需要给命名空间加引号来明确边界，例如 `"ext".版本1.0 完成:`，也可以使用显式 opcode 调用。

这个名称只用于 DSL 查找，与 `import` 模块名、自制积木名、`getInfo().id` 分别管理，不改变扩展运行时 ID 或生成的 opcode。

## 调用

以下示例假设扩展注册了对应模板，实际文字由 `getInfo()` 决定。

| 积木类型 | 写法 |
| --- | --- |
| 命令 | `自定义拓展.移动(10)步` |
| 报告 | `(自定义拓展.结果数量)` |
| 布尔 | `<自定义拓展.已就绪 ?>` |
| 帽子（`hat` / `event`） | `自定义拓展.当计算完成:` 后换行缩进写命令 |
| C 型控制积木 | `自定义拓展.完整文字与输入:` 后换行缩进写分支体 |

第三方积木每次调用都要写前缀。`移动(10)步` 查找原版和当前可见的自制积木；`自定义拓展.移动(10)步` 只查这个扩展，因此两者可以有相同显示文字。命名空间不存在或没有匹配模板时报错，不回退到其他扩展或原版积木。

命名空间、点号和积木起始之间不能有空白或注释。嵌套积木各写自己的前缀，帽子前缀也不影响事件体中的积木。普通值和变量/列表目标槽用圆括号，例如 `(变量)`、`(@参数)`；布尔槽用尖括号。接受报告积木的菜单槽写 `('选项')`，不接受报告积木的菜单字段写 `'选项'`，与选项来源是静态数组还是动态方法无关。

```scratch
sprite "玩家":
    init:
        pass
    start:
        移动(10)步
        自定义拓展.移动(10)步
        说(自定义拓展.结果数量)
        自定义拓展.记录(x 坐标)
        if <自定义拓展.已就绪 ?>:
            自定义拓展.执行计算

    自定义拓展.当计算完成:
        说("完成")
```

值位置的命名空间和后面的积木作为一个表达式解析。例如 `("inner".x 坐标)` 不能拆成字符串 `"inner"`、外层固定文字 `.` 和原版报告积木。双引号名称后紧接 `.` 与积木文字时，优先识别这种调用；帽子则结合整个头部末尾的冒号和缩进脚本判断，头部也可以从参数开始。

## C 型控制积木

`conditional`、`loop` 和带正数 `branchCount` 的 `command` 使用 C 型语法，只能放在事件、自制积木或段积木体内。头部仍是带命名空间的完整积木调用，末尾加 `:`；第一个缩进体是第一分支，后续分支依次使用与头部同级的 `else:`，缩进回退到调用所在层级后继续后面的语句，文件结束也会结束代码体。每个分支都必须写出，空分支必须缩进写 `pass`。

例如扩展注册以下元信息：

```javascript
{
  opcode: "choose",
  blockType: Scratch.BlockType.CONDITIONAL,
  branchCount: 2,
  text: ["当 [READY]", "否则延迟 [DELAY]"],
  arguments: {
    READY: {type: Scratch.ArgumentType.BOOLEAN},
    DELAY: {type: Scratch.ArgumentType.NUMBER}
  }
}
```

调用时，按 `text` 数组的顺序把全部文字和输入写在同一个头部：

```scratch
ext.当<ready = 1>否则延迟(2):
    score += 1
else:
    score -= 1
```

`else:` 只划分脚本体，不重复扩展的显示文字或输入。三个或更多分支时继续写同级 `else:`，数量必须与元信息一致；扩展分支不使用 `elif`。生成的子栈依次名为 `SUBSTACK`、`SUBSTACK2`、`SUBSTACK3` 等，循环是否继续、执行哪个分支仍由扩展运行时代码决定。

`conditional`、`loop` 的 `branchCount` 缺省或为 `0` 时按一个分支处理；显式非零分支数须为 JavaScript 安全正整数。`command` 缺省或为 `0` 时仍是普通命令，正整数才产生 C 型积木。`text` 可以是字符串或字符串数组，数组元素按顺序用空格连接，数组长度不限定分支数。

## 指定 opcode

显示文字有歧义或包含不便书写的语法符号时，可以直接指定 `getInfo().blocks[].opcode`。这里只写扩展内的 opcode，不加扩展 ID：

| 类型 | 带参数 | 无参数 |
| --- | --- | --- |
| 命令 | `ext::"move"((10), 'left')` | `ext::"clear"()` |
| 报告 | `(ext::"read"((score)))` | `(ext::"count"())` |
| 布尔 | `<ext::"contains"(("内容"))>` | `<ext::"ready"()>` |
| 帽子 | `ext::"when"('space'):` | `ext::"done"():` |
| C 型控制积木 | `ext::"choose"(<ready = 1>, (2)):` | `ext::"run"():` |

`ext` 代表扩展的命名空间，可以来自文件名或 `as` 别名，例如 `自定义拓展`。命名空间、`::`、双引号 opcode 和参数列表起始 `(` 必须紧贴，opcode 后不再加点号。所有形状共用这套写法，报告/布尔调用再由所在输入槽的 `(...)` 或 `<...>` 包住，帽子和 C 型调用末尾加冒号。opcode 字符串沿用普通字符串转义。

编译器按命名空间和 opcode 查到模板后，按槽位在显示文字中的出现顺序读取参数，而不是 `arguments` 对象的键顺序。参数用顶层逗号分隔，每项仍必须按槽位类型包裹：普通槽 `(值)`、布尔槽 `<条件>`、不接受报告积木的菜单字段 `'选项'`。表中的 `'left'`、`'space'` 假设对应菜单的 `acceptReporters` 为 `false`；为 `true` 时应改为 `('left')`、`('space')`。最外层圆括号只是参数列表，不能代替各槽位的括号。参数不能省略或带尾逗号，也不写模板文字；零参数时留空。字符串、菜单和嵌套积木内的逗号属于内部内容。

旧 `.[]`、`.()`、`.<>`、`.hat()` 显式调用形式不再接受。这种写法只跳过显示文字匹配，仍校验形状、参数数量和类型、角色/舞台限制。C 型积木的缩进体和 `else:` 与普通文字调用相同，分支数也必须符合元信息。未知或重复 opcode、缺少元信息、不支持的积木类型都会报错，不会猜测参数。

## 重复来源与冲突

同一文件以同一命名空间重复配置时只加载一次；给同一文件配置不同名字会报错，不能同时保留文件名和别名两套前缀。文件身份按规范化绝对路径判断，消除 `.`、`..`，解析符号链接，并遵循文件系统的大小写规则。

不同文件出现以下情况会报错，并指出冲突来源：

- 最终命名空间相同，包括文件名与别名之间的冲突。
- `getInfo().id` 相同，即使命名空间不同。
- 生成的完整 opcode 与原版或其他已注册积木冲突。

命名空间允许显示文字相同，但不改变运行时 opcode，因此不能解决后两种冲突。

支持 `command`、`reporter`、`Boolean`、`hat`、`event`、`conditional` 和 `loop`。菜单、参数类型和元信息校验见[模板引擎](./templates.md)。

打包时扩展源码内嵌到 `.sb3` 的 `extensionURLs`，格式为 `data:application/javascript;charset=utf-8;base64,...`，不写入本地文件路径，也没有关闭内嵌的开关。这里的 data URI 是运行时数据，不是配置输入；加载仍只使用本地文件。
