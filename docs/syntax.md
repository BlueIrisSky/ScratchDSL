# 语法与积木

ScratchDSL 使用 Python 风格的冒号、换行和缩进表示代码体。命令直接写文字，输入槽使用括号，不能再把整条命令包在 `[]` 中。

| 写法 | 用途 | 例子 |
| --- | --- | --- |
| 裸命令文字 | 执行一条命令 | `移动(10)步`、`说("你好")(2)秒` |
| `(...)` | 普通值、报告积木或变量/列表目标输入槽 | `移动(score)步`、`说(x 坐标)`、`显示变量(score)` |
| `<...>` | 布尔输入槽 | `等待直到<碰到('鼠标指针')?>`、`if <score > 100>:` |
| `'...'` | 不接受报告积木的菜单字段 | `停止'全部脚本'` |
| `"..."` | 广播接收事件的名称字段 | `当收到广播 "跳跃":` |
| `{ ... }` | 列表字面量 | `logs = {"开始", 1}` |
| `头部:` 后换行并缩进 | 角色、事件、自制积木、段积木或控制流的代码体 | `start:`、`piece:`、`if <score > 100>:` |
| `end` | 结束事件、自制积木、段积木或控制流 | `if <score > 100>:` … `end` |

所有接受报告积木的普通非布尔输入槽都必须写 `(...)`，即使内容只是数字、字符串、变量或菜单。比如 `等待(1)秒`，不能省略成 `等待 1 秒`。括号紧贴固定文字时可省略空白，也可写成 `等待 (1) 秒`。嵌套报告积木仍按自己的槽位加括号：`说(连接("你好")和("世界"))`。布尔输入使用 `<...>`；广播接收事件的名称是固定字段，直接写双引号字符串。

第三方命令加[扩展命名空间](extensions.md)，例如 `ext.移动(10)步`；值和布尔调用的前缀写在输入括号内，例如 `说(ext.数字)`、`等待直到<ext.就绪>`。`init:` 的缩进体是[初始化数据](sprites.md#角色初始状态)，其中资源数组仍使用 JSON 风格的 `[]`。

## 空白与注释

代码体的头部以 `:` 结束，下一条有效语句必须另起一行并增加缩进；同级语句使用相同缩进。`sprite`、`stage`、`init`、事件、自制积木、段积木和控制流都必须在最后一个成员或分支之后、与头部相同缩进的位置写 `end`。建议每级使用四个空格。空行和注释不改变层级，LF / CRLF 均可。空代码体可以直接写 `end`，也可以写一条 `pass`。输入括号里的换行和空格一样，不会分隔语句；字符串、菜单和带引号名称中的空白原样保留。

一条命令占一条逻辑行。输入太长时，可以在 `()`、`<>` 内换行；列表字面量也可在 `{}` 内换行：

```scratch
start:
    hp = (
        base + bonus
    )
    等待(
        hp
    )秒
end
```

注释只用 `#`，按下面的顺序识别：

1. 本行还有另一个 `#`：从当前 `#` 注释到本行下一个 `#`，之后继续读取代码。
2. 本行没有后续 `#`，且当前 `#` 独占一行：开始跨行注释，直到后续第一个 `#`。文件结束时仍未闭合会报错。
3. 其他情况：从当前 `#` 注释到行尾。

```scratch
# 单行注释
# 行内块注释 # score = 0
#
这段注释可以写多行。
到下一处井号结束。
#
```

块注释不嵌套。注释按空白处理，并保留换行。字符串和菜单内的 `#` 是内容；`//`、`/*` 都不是注释。

## 名称与字面量

普通标识符以 Unicode 字母或 `_` 开头，后面可接 Unicode 字母、十进制数字或 `_`。名称区分大小写，不做 Unicode 归一化。点号、冒号、运算符、空白和括号不属于普通标识符。

变量和列表名称只允许普通标识符，不支持空格或带引号名称。直接赋初值，编译器根据右侧推断变量或列表；不再使用 `var`、`list` 声明：

```scratch
我的分数 = 0
任务列表 = {}
```

首次赋值确定数据种类，例如 `我的分数 = 0` 创建变量，`任务列表 = {}` 创建列表；后续不能把变量改成列表，也不能把列表改成变量。名称本身不加前缀，但在积木输入槽中必须加相应括号：`移动(我的分数)步`、`删除(任务列表)的全部项目`。赋值和算术语法糖仍直接使用名称，例如 `我的分数 += 1`。普通过程参数填入输入槽时写 `(@"a b")`，布尔参数写 `<@"a b">`；定义中也可以用 `(名称)`、`<名称>` 声明同样的槽位。角色名始终加双引号。扩展命名空间另见[扩展加载](extensions.md)。

普通 DSL 字符串用双引号包住，只支持 `\"`、`\\`、`\n`、`\r` 四种转义，其他转义会报错。字符串不能直接跨物理行，换行、回车用转义表示；其中的 `/` 和 `#` 都是普通字符。文本值必须加引号，裸文字只能是模板中的固定文字或标识符。例如 JSON 文本要写成 `"[1, 2, 3]"` 或 `"{ \"key\": 1 }"`。这些限制也适用于带引号的名称；`init` 和构建配置的字符串则支持完整 JSON 转义，见[初始化数据](sprites.md#角色初始状态)。

数值接受 `10`、`0.5`、`.5`、`-90`、`1e-5`、`2E+3` 等形式，完整形式为：

```text
-?(digits(\.digits)?|\.digits)([eE][+-]?digits)?
```

这里的 `digits` 是一个或多个 ASCII 数字 `0` 到 `9`。不接受前导 `+`、尾点 `1.`、十六进制、`NaN` 或 `Infinity`，记号中间也不能插入空白或注释。数值按 IEEE 754 双精度解析，溢出为非有限值会报错。解析器总是读取最长的合法数值记号，不会把 `123` 拆成多个参数，也不会拆开 `1e-5`。

## 变量、列表与参数

数据种类由赋值的右侧推断：`{...}` 创建列表，其他合法赋值创建变量。文件或角色定义体中的变量初值只能是数值或字符串；脚本内还可以使用参数、报告积木、布尔积木或算式。不使用 `var`、`list` 或 `global var` 声明。

```scratch
score = 0
logs = {"开始", 1}
global:level = 1
```

文件顶层的初值定义创建全局数据；角色创建或追加体中创建私有数据。`global:名称` 显式选择全局数据。定义初值只接受数值、字符串或由这些字面量组成的列表，不接受运行时表达式。列表元素用逗号分隔，不允许尾逗号和嵌套列表。

| 使用位置 | 例子 |
| --- | --- |
| 读取变量的普通输入槽 | `移动(score)步`、`说(global:score)` |
| 变量目标槽 | `显示变量(score)` |
| 列表目标槽 | `将(score)加入(logs)`、`删除(global:logs)的全部项目` |
| 字符串/数值参数槽 | `移动(@steps)步`、`说(@"参数 名")` |
| 布尔参数槽 | `等待直到<@ready>` |
| 赋值、算术与控制流语法糖 | `score += 1`、`score = a+b*2`、`loop count:` |

数据名称只允许普通标识符，唯一的作用域前缀是 `global:`。旧 `$score`、`var:score`、`list:logs`、`global:list:logs` 和带引号的数据名均不接受。`"score"` 是字符串，`score` 是数据名；输入槽要分别写成 `("score")`、`(score)`。

种类一旦确定就不能转换。`score = {}`、`logs = 1`、`score = logs`、`将(1)加入(score)`、`说(logs)` 都会报错。读取列表中的普通值需要列表报告积木，例如 `说((logs)的项目数)`、`说((logs)的第(1)项)`。

同一作用域或全局与角色的可见作用域之间，不能有种类不同的同名数据；不同角色互不可见的私有数据独立检查。编译器先收集赋值并确定种类，再解析引用，因此可以引用后面才赋值的数据；种类不取决于哪个事件先运行。相同种类的重复初值定义按模块展开顺序覆盖。普通引用先查角色私有数据，再查全局数据；公共自制积木只查全局数据。未定义的变量引用会创建初值为 `0` 的全局变量；未定义列表会报错。详见[变量和列表](sprites.md#变量和列表)。

固定积木文字由模板识别，不作为变量。`移动(speed)步` 中的 `移动`、`步` 是固定文字；`(计时器)` 等已注册报告积木优先匹配同名普通标识符。

参数只能在定义它的自制积木内使用。未知参数、类型不符或过程外参数引用都会报错。普通参数生成 `argument_reporter_string_number`，布尔参数生成 `argument_reporter_boolean`。定义头可以使用 `@名称`、`<@名称>`，也可以使用 `(名称)`、`<名称>`；末尾 `@warp` 属性保留。`warp` 不能作为参数名，写成 `@"warp"` 也不行。

## 赋值

文件或角色定义体中的 `名称 = 初值` 设置静态初值。事件、自制积木、段积木和控制流内部的赋值在运行时执行；变量支持 `=`、`+=`、`-=`、`*=`、`/=`、`%=`，两侧空格可省略。

```scratch
score = 0
logs = {}
start:
    score = 10
    score += 1
    score -= 2
    score *= 3
    score /= 2
    score %= 5
    score = a+b-c*d/f%e
    global:score = score
    score = (计时器)
    logs = {"重新开始", 1}
end
```

变量赋值右侧可以是数值、字符串、变量、参数、报告积木、有值的布尔积木或算式。赋值和算术语法糖的操作数不强制包输入括号；嵌入普通报告积木时，其自身的各输入槽仍必须加括号，例如 `score = (连接("文字")和(score))`。跨行算式用括号分组。复合赋值执行 Scratch 数值运算。

脚本中的列表赋值先清空目标列表，再按顺序加入字面量元素；`logs = {}` 清空列表。列表元素只接受数值和字符串，不支持列表复制、嵌套列表或运行时元素表达式。脚本中新出现的名称创建全局数据，已存在的角色私有数据仍按原作用域使用；后续赋值必须保持首次确定的种类。错误种类会在 IDE 标红。

赋值左侧是单个数据名，可用 `global:` 指定全局，不能是参数或报告积木。比较相等仍写 `<score = 10>`。旧 `var` / `list` 声明、中文变量“设为”“增加”命令，以及 `[score = 10]` 这样的方括号写法均不接受。

## 运算符

算术运算使用普通符号，小于、大于和等于分别写成 `<`、`>`、`=`。比较表达式的外层仍用 `<...>` 表示布尔积木，VS Code 会分别高亮外层括号和内部运算符。

| 运算 | 写法 | 例子 |
| --- | --- | --- |
| 加法 | `+` | `(1 + 2)` |
| 减法 | `-` | `(3 - 1)` |
| 乘法 | `*` | `(2 * 3)` |
| 除法 | `/` | `(8 / 2)` |
| 取余 | `%` | `(7 % 3)` |
| 小于 | `<` | `<hp < 1>` |
| 大于 | `>` | `<score > 100>` |
| 等于 | `=` | `<score = 100>` |

`与`、`或`、`不成立` 保持文字写法，例如 `<<true> 与 <false>>`。负数字面量、指数中的负号和赋值用的 `=` 按原写法：`-90`、`1e-5`、`score = 0`。在 `(1 - -2)` 中，第一个 `-` 是减法，`-2` 是负数。

这些中缀运算符两侧的空白可以省略，例如 `(1+2)`、`<hp<1>`。

算术表达式自动按优先级展开为 Scratch 运算积木：分组括号优先，随后是 `* / %`，最后是 `+ -`；同级运算从左到右结合。表达式支持负数和一元负号。变量直接写名称，参数写 `@参数`。

```scratch
(a+b-c*d/f%e)
((a+b)*c)
(1 + 2 * 3)
<<1 < 2> 与 <2 < 3>>
```

例如 `(a+b-c*d/f%e)` 展开为 `((a+b)-(((c*d)/f)%e))` 对应的运算积木树，在 Scratch 运行时计算。已有的 `(x 坐标)`、`(连接("a")和("b"))` 报告积木仍按模板匹配。比较和布尔连接仍按显式积木嵌套，连续比较 `<1 < 2 < 3>` 不合法。

扩展命名空间可以含 `-`。算术表达式中的扩展报告调用保留自己的圆括号，例如 `(score-(ext.数字))` 或 `(score - (ext.数字))`；`(score-ext.数字)` 则是命名空间 `score-ext` 的报告调用。

解析器根据左右操作数和当前积木的完整边界区分比较符号与括号。`<score > 100>` 中间的 `>` 是比较运算符，最后的 `>` 结束布尔积木。`/` 表示除法，单引号表示菜单，因此 `(8 / 2)` 是除法，菜单 `'*'` 的值为 `*`。

## 布尔输入与菜单

布尔槽位接受布尔积木，也接受 `<true>`、`<false>` 和 `<>`。

`<true>` 相当于 `<1 = 1>`，`<false>` 相当于 `<1 = 0>`。

`<>` 表示布尔输入未连接，括号内允许只有空白。它不生成布尔积木，也不等于 `<false>`，只能放在要求布尔输入的槽位里，不能作为数值、字符串或独立表达式。例如 `<不成立 <>>` 合法。显式 opcode 调用 `<ext::"ready"()>` 则表示扩展的零参数布尔积木，仍需查找并校验其定义，不是空槽。

菜单内容用单引号包住。不接受报告积木的菜单字段直接写 `'选项'`；接受报告积木的菜单槽必须写 `('选项')`。例如 `'鼠标指针'`、`'space'`、`'全部脚本'`。空菜单写成 `''`，用于接受报告积木的槽时写 `('')`。

单引号内可以包含空格、双引号、`/`、`*`、`#`，首尾空格原样保留。需要单引号或反斜杠时写 `\'`、`\\`；其他转义与 JSON 一致，包括 `\n`、`\r`、`\t`、`\b`、`\f`、`\/`、`\"`、`\uXXXX`。菜单不能跨物理行。

```scratch
''
'a/b'
'a"b'
'it\'s'
'a\nb'
'/'
'*'
```

菜单不再需要两侧的 `/`。单引号内的 `/` 是内容。`/space/`、`/"space"/` 和 `//` 都不是合法菜单。普通字符串继续使用双引号。

静态菜单先按存储值 `value` 精确匹配；没有匹配时，再接受能唯一定位选项的显示文字 `text`。同一显示文字对应多个不同值会报错，指向同一个值的显示文字别名可合并。动态菜单保存传入值，不校验它是否属于某个静态选项表。

菜单槽的 `acceptReporters` 为 `false` 时，只接受裸单引号菜单字面量；为 `true` 时，一律要求圆括号输入，括号中可填菜单、普通值、报告积木或有值的布尔积木，但不接受空槽 `<>`。例如 `移到('鼠标指针')` 与 `停止'全部脚本'` 使用不同槽位形式。按键事件写 `当按下 'space' 键:`，按键侦测写 `<按下('space')键?>`；两者的选项表都是静态的，但只有侦测槽接受报告积木。是否加圆括号取决于 `acceptReporters`，与选项表是静态还是动态无关。这些非菜单表达式不检查菜单成员。变量、列表等内置符号字段使用对应引用语法。

以上形式并非每个槽位都能使用，仍要满足该槽位的类型和菜单设置。嵌套积木可使用普通调用、命名空间调用或显式 opcode 调用；第三方积木始终需要前缀。扩展的 `angle` 接受普通数值，颜色字面量是 `"#rrggbb"`，其中六位均为十六进制数字。目前不支持 `matrix`、`note`、`image` 参数，显式 opcode 也不能绕过限制。字段、输入及类型校验详见[模板定义](templates.md)。

## 模板如何匹配

积木文字按注册模板匹配。模板固定文字中的连续空白合并为一个空格，模板首尾空白忽略；输入括号内首尾的语法空白也忽略。固定文字内部的规范化空格仍要求语法空白，输入括号与相邻固定文字之间可以省略空白；例如 `等待(1)秒` 与 `等待 (1) 秒` 等价。字符串、菜单、名称的内容不参与这项处理，固定文字和槽位的顺序也不会改变。

每个槽位按类型读取完整输入：普通值和变量/列表目标用 `(...)`，布尔用 `<...>`，不接受报告积木的菜单用单引号，广播接收事件的名称字段用双引号字符串。首槽和尾槽可以直接接在积木内容的开头或结尾，不要求两边都有固定文字。嵌套积木的命名空间与显式 opcode 前缀也是这个值的一部分，不能拿来匹配外层固定文字。

相邻槽位可直接相接，例如 `说("你好")(2)秒`；输入括号和菜单引号提供边界。模板中的固定文字仍要保留，例如 `连接("a")和("b")` 不能省略 `和`。数值和标识符不能任意拆开：`123` 不能拆成 `1`、`23`，`1-2` 也不能拆成 `1`、`-2`。同一个模板若仍能得到多种不同的完整参数划分，会报歧义错误。

模板必须匹配整个积木内容，并且每个槽位都通过类型和字段校验，不能剩下多余的前缀、尾部文字或参数。角色普通调用先用同签名的私有自制积木遮蔽公共定义，再把可见的自制积木与内置模板一起匹配；带扩展前缀时只匹配指定命名空间。

没有有效匹配时报错。有多个有效匹配时，取固定文字总长度最长的模板，长度按规范化后的 Unicode 码点数计算，包括规范化的空格。指向相同 opcode 且槽位绑定相同的内置别名可以合并；合并后仍有多个同样长的不同结果，就报歧义错误，不按注册先后选择。

自制积木签名由按顺序排列的固定文字和槽位类型组成，保留槽位位置，忽略参数名。字符串/数值共用一种槽位类型，布尔是另一种；只改参数名不会得到新的签名。

## 段积木

Scratch 中的积木可以是一段没有事件帽子的独立积木。`piece:` 用来把这样一段积木原样编译进 `.sb3`，它不会自动执行：

```scratch
piece:
    说("这段积木不会自己运行")
    if <score > 0>:
        说("可以作为素材拖进其他脚本")
    end
end
```

段积木写在文件顶层或 `stage:` 中时属于舞台，写在角色创建或追加体中时属于该角色。它只能出现在这些成员位置，不能出现在事件、自制积木、控制流或另一个段积木内部；段积木内部可以继续写控制流，但不能写事件或另一个 `piece:`。空的段积木直接写 `piece:` 后接 `end`。

## 事件与控制流

事件写在文件顶层时属于舞台，写在 `sprite` 创建或追加体中时属于该角色。第三方事件写成 `命名空间.帽子文本:` 并缩进脚本，归属规则相同。

```scratch
sprite "事件示例":
    init:
        pass
    end
    start:
        score = 0
        说("游戏开始！")(2)秒
    end

    当角色被点击:
        score += 1
    end

    当按下 'space' 键:
        广播("跳跃")
    end

    当收到广播 "跳跃":
        将 y 坐标增加(50)
    end
end
```

解析事件时先识别完整帽子头和缩进体，根据所处位置选择事件帽子模板。帽子模板可以以槽位开头，例如 `ext.(x 坐标) 达标:`；这里的 `(x 坐标)` 可以是帽子的第一个参数。头部结束的冒号必须位于字符串、菜单和嵌套积木之外。显式 `ext::"opcode"(...)` 调用根据当前位置选择帽子模板。

以下控制流写在事件、自制积木或段积木内部，不能单独放在文件顶层。内置控制流使用下列关键字，第三方 C 型积木使用带命名空间的调用头。

```scratch
loop 10:
    移动(10)步
end

loop count:
    右转(15)度
end

while true:
    移动(5)步
    碰到边缘就反弹
end

while <hp > 0>:
    等待(1)秒
end

if <碰到('边缘')?>:
    说("撞墙了！")
end

if <score > 100>:
    说("通关！")
elif <score > 50>:
    说("快到了！")
else:
    说("继续努力")
end
```

`loop N:` 对应 `control_repeat`。`while <条件>:` 在条件为真时循环，直接生成 `control_while`；`while true:` 直接生成 `control_forever`。两种条件分支对应 `control_if` 和 `control_if_else`。每个 `elif` 展开为前一个分支的否则体中的条件积木，条件按顺序判断，最多执行一个分支。`elif` 和 `else` 必须紧接同级 `if` / `elif`，并使用相同缩进。

扩展注册的 C 型积木写成 `命名空间.完整积木文字与输入:`，例如：

```scratch
ext.当<ready = 1>否则:
    score += 1
else:
    score -= 1
end

ext::"repeat"((count)):
    移动(1)步
end
```

第一个缩进体对应第一分支；每个后续分支使用与调用头同级的 `else:`，三个以上分支可继续重复。分支数量必须与扩展元信息一致，空分支写 `pass`，扩展分支不使用 `elif`。多段 `text` 数组的文字和输入按原顺序全部写在同一个调用头，显式 opcode 调用则按相同顺序提供参数。元信息、默认分支数和运行行为见[扩展 C 型控制积木](extensions.md#c-型控制积木)。

结构关键字不加 `@`：`stage`、`sprite`、`init`、`piece`，自制积木用 `def 模板:`。事件、自制积木、段积木和控制流必须在同级缩进写 `end`。变量和列表用赋值推断种类，不再使用声明关键字。参数引用和 `@warp` 属性保留原写法。旧大括号代码体、省略 `end` 的代码体、带 `@` 的声明、中文控制流与绿旗事件、`repeat` / `until` / `forever`、列表 `[]` 初值和 `/'选项'/` 均不再接受。
