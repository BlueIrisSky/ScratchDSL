# 语法与积木

ScratchDSL 用括号表示积木形状，用花括号包住脚本。

| 写法 | 用途 | 例子 |
| --- | --- | --- |
| `[...]` | 命令积木，没有返回值 | `[移动 10 步]`、`[说 "你好" 2 秒]` |
| `(...)` | 报告积木，返回数值或字符串 | `(x 坐标)`、`(连接 "分数: " 和 $score)` |
| `<...>` | 布尔积木，返回真假 | `<碰到 /'鼠标指针'/ ?>`、`<$score > 100>` |
| `{ ... }` | 角色、事件、自制积木或控制流的代码体 | `重复执行 10 次 { [移动 10 步] }` |

第三方积木也使用这套括号，但必须带[扩展命名空间](extensions.md)。`@init { ... }` 里面是[初始化数据](sprites.md#角色初始状态)：用 `字段名: 值` 设置角色属性，与构建配置使用相同的数据写法。

## 空白与注释

空格、制表符和 LF / CRLF 换行都是语法空白。缩进和空行不影响含义，同级语句之间必须换行。代码体只有一条语句时可以写成 `{ [说 "你好"] }`；积木括号里的换行则和空格一样，不会分隔语句。字符串、菜单和带引号名称中的空白原样保留。

积木太长时，可以在 `[]`、`()`、`<>` 内直接换行，不需要逗号或续行符：

```scratch
当绿旗被点击 {
    [将 $hp
        设为 100]
}
```

注释只用 `#`，按下面的顺序识别：

1. 本行还有另一个 `#`：从当前 `#` 注释到本行下一个 `#`，之后继续读取代码。
2. 本行没有后续 `#`，且当前 `#` 独占一行：开始跨行注释，直到后续第一个 `#`。文件结束时仍未闭合会报错。
3. 其他情况：从当前 `#` 注释到行尾。

```scratch
# 单行注释
# 行内块注释 # @var score = 0
#
这段注释可以写多行。
到下一处井号结束。
#
```

块注释不嵌套。注释按空白处理，并保留换行。字符串和菜单内的 `#` 是内容；`//`、`/*` 都不是注释。

## 名称与字面量

普通标识符以 Unicode 字母或 `_` 开头，后面可接 Unicode 字母、十进制数字或 `_`。名称区分大小写，不做 Unicode 归一化。点号、冒号、运算符、空白和括号不属于普通标识符。

变量、列表和参数的名称含其他字符时，加双引号。解码后相同的名称指向同一个对象，引号不算名称的一部分：

```scratch
@var "a b" = 0
@list "任务 列表" = []
```

它们的引用分别是 `$"a b"`、`$list:"任务 列表"`；参数可以写成 `@"a b"` 或 `<@"a b">`。角色名始终加双引号。扩展命名空间另见[扩展加载](extensions.md)。

普通 DSL 字符串用双引号包住，只支持 `\"`、`\\`、`\n`、`\r` 四种转义，其他转义会报错。字符串不能直接跨物理行，换行、回车用转义表示；其中的 `/` 和 `#` 都是普通字符。文本值必须加引号，裸文字只能是模板中的固定文字或标识符。例如 JSON 文本要写成 `"[1, 2, 3]"` 或 `"{ \"key\": 1 }"`。这些限制也适用于带引号的名称；`@init` 和构建配置的字符串则支持完整 JSON 转义，见[初始化数据](sprites.md#角色初始状态)。

数值接受 `10`、`0.5`、`.5`、`-90`、`1e-5`、`2E+3` 等形式，完整形式为：

```text
-?(digits(\.digits)?|\.digits)([eE][+-]?digits)?
```

这里的 `digits` 是一个或多个 ASCII 数字 `0` 到 `9`。不接受前导 `+`、尾点 `1.`、十六进制、`NaN` 或 `Infinity`，记号中间也不能插入空白或注释。数值按 IEEE 754 双精度解析，溢出为非有限值会报错。解析器总是读取最长的合法数值记号，不会把 `123` 拆成多个参数，也不会拆开 `1e-5`。

## 变量、列表与参数

| 引用 | 含义 |
| --- | --- |
| `$score` | 变量，先查角色私有数据，再查全局数据 |
| `$list:logs` | 列表，查找顺序同上 |
| `$global:score` | 显式引用全局变量 |
| `$global:list:logs` | 显式引用全局列表 |
| `@steps` | 当前自制积木的字符串/数值参数 |
| `<@ready>` | 当前自制积木的布尔参数 |

变量和列表前缀按最长形式识别：`$global:list:`、`$global:`、`$list:`、`$`。前缀后可以接普通名称或带引号名称，例如 `$global:"a b"`、`$global:list:"a b"`。

`[移动 $speed 步]` 读取变量的值，`[将 $score 设为 0]` 则把变量作为操作目标。列表引用也要按所在槽位的类型使用。找不到变量时会在舞台上创建初始值为 `0` 的全局变量；找不到列表会报错。显式全局引用也遵循这条规则。作用域规则见[角色与自制积木](sprites.md#变量和列表)。

参数只能在声明它的自制积木内部使用。未知参数、类型不符或过程外的参数引用都会报错。字符串/数值参数生成 `argument_reporter_string_number`，布尔参数生成 `argument_reporter_boolean`。`@warp` 是定义头末尾的属性，不能用作参数名，写成 `@"warp"` 也不行。

## 运算符

算术运算使用普通符号，小于、大于和等于分别写成 `<`、`>`、`=`。比较表达式的外层仍用 `<...>` 表示布尔积木，VS Code 会分别高亮外层括号和内部运算符。

| 运算 | 写法 | 例子 |
| --- | --- | --- |
| 加法 | `+` | `(1 + 2)` |
| 减法 | `-` | `(3 - 1)` |
| 乘法 | `*` | `(2 * 3)` |
| 除法 | `/` | `(8 / 2)` |
| 取余 | `mod` | `(7 mod 3)` |
| 小于 | `<` | `<$hp < 1>` |
| 大于 | `>` | `<$score > 100>` |
| 等于 | `=` | `<$score = 100>` |

`与`、`或`、`不成立` 保持文字写法，例如 `<<true> 与 <false>>`。负数字面量、指数中的负号和声明用的 `=` 按原写法：`-90`、`1e-5`、`@var score = 0`。在 `(1 - -2)` 中，第一个 `-` 是减法，`-2` 是负数。

这些中缀运算符两侧的空白可以省略，例如 `(1+2)`、`<$hp<1>`；但不能让运算符与名称合成一个标识符，因此变量与 `mod` 之间仍需空白，例如 `($score mod 3)`。

每层中缀运算或布尔连接只能有一个运算符。没有隐式优先级，也不支持连续比较，需要运算的部分应各自写成积木：

```scratch
(1 + (2 * 3))
<<1 < 2> 与 <2 < 3>>
```

`(1 + 2 * 3)` 和 `<1 < 2 < 3>` 都会报错。负数字面量的负号不计作本层运算符。`(...)` 始终表示报告积木，不是数学分组括号，因此 `(1)` 不能代替 `1`。

解析器根据左右操作数和当前积木的完整边界区分比较符号与括号。`<$score > 100>` 中间的 `>` 是比较运算符，最后的 `>` 结束布尔积木。`/` 在二元运算中表示除法，菜单则必须以 `/'` 开始，因此 `(8 / 2)` 是除法，菜单 `/'*'/` 的值为 `*`。

## 布尔输入与菜单

布尔槽位接受布尔积木，也接受 `<true>`、`<false>` 和 `<>`。

`<true>` 相当于 `<1 = 1>`，`<false>` 相当于 `<1 = 0>`。

`<>` 表示布尔输入未连接，括号内允许只有空白。它不生成布尔积木，也不等于 `<false>`，只能放在要求布尔输入的槽位里，不能作为数值、字符串或独立表达式。例如 `<不成立 <>>` 合法。显式 opcode 调用 `ext::"ready".<>` 则表示扩展的零参数布尔积木，仍需查找并校验其定义，不是空槽。

菜单固定写成 `/'选项'/`，内容必须用单引号包住。例如 `/'鼠标指针'/`、`/'space'/`、`/'全部脚本'/`。空菜单写成 `/''/`。

单引号内可以包含空格、双引号、`/`、`*`、`#`，首尾空格原样保留。需要单引号或反斜杠时写 `\'`、`\\`；其他转义与 JSON 一致，包括 `\n`、`\r`、`\t`、`\b`、`\f`、`\/`、`\"`、`\uXXXX`。菜单不能跨物理行。

```scratch
/''/
/'a/b'/
/'a"b'/
/'it\'s'/
/'a\nb'/
/'/'/
/'*'/
```

起始单引号紧跟 `/`，结束单引号后紧接 `/`，中间不能插入空白或注释。单引号内的 `/` 不会结束菜单。`/space/`、`/"space"/` 和 `//` 都不是合法菜单。普通字符串继续使用双引号。

静态菜单先按存储值 `value` 精确匹配；没有匹配时，再接受能唯一定位选项的显示文字 `text`。同一显示文字对应多个不同值会报错，指向同一个值的显示文字别名可合并。动态菜单保存传入值，不校验它是否属于某个静态选项表。

普通菜单槽的 `acceptReporters` 为 `false` 时，只接受菜单字面量；为 `true` 时，也接受值表达式，包括报告积木和有值的布尔积木，但不接受空槽 `<>`。这些非菜单表达式不检查菜单成员。变量、列表等内置符号字段使用对应引用语法。

以上形式并非每个槽位都能使用，仍要满足该槽位的类型和菜单设置。嵌套积木可使用普通调用、命名空间调用或显式 opcode 调用；第三方积木始终需要前缀。扩展的 `angle` 接受普通数值，颜色字面量是 `"#rrggbb"`，其中六位均为十六进制数字。目前不支持 `matrix`、`note`、`image` 参数，显式 opcode 也不能绕过限制。字段、输入及类型校验详见[模板定义](templates.md)。

## 模板如何匹配

积木文字按注册模板匹配。模板固定文字中的连续空白合并为一个空格，模板首尾空白忽略；源码积木括号内首尾的语法空白也忽略。除上述内置中缀运算符外，一个规范化后的空格要求源码中至少有一个语法空白，不能随意删掉文字之间或参数前后的空白。字符串、菜单、名称的内容不参与这项处理，固定文字和槽位的顺序也不会改变。

每个槽位必须读到一个完整的值：字符串、数值、引用、菜单或嵌套积木。首槽和尾槽可以直接接在积木内容的开头或结尾，不要求两边都有固定文字。嵌套积木的命名空间与显式 opcode 前缀也是这个值的一部分，不能拿来匹配外层固定文字。

相邻槽位通常用空白分开。前一个值已有明确结束符时，可以直接相接，例如 `"a""b"`；字符串引号、菜单结尾的 `/` 和积木闭括号都属于这种结束符。数值和标识符不能任意拆开：`123` 不能拆成 `1`、`23`，`1-2` 也不能拆成 `1`、`-2`。同一个模板若仍能得到多种不同的完整参数划分，会报歧义错误。

模板必须匹配整个积木内容，并且每个槽位都通过类型和字段校验，不能剩下多余的前缀、尾部文字或参数。角色普通调用先用同签名的私有自制积木遮蔽公共定义，再把可见的自制积木与内置模板一起匹配；带扩展前缀时只匹配指定命名空间。

没有有效匹配时报错。有多个有效匹配时，取固定文字总长度最长的模板，长度按规范化后的 Unicode 码点数计算，包括规范化的空格。指向相同 opcode 且槽位绑定相同的内置别名可以合并；合并后仍有多个同样长的不同结果，就报歧义错误，不按注册先后选择。

自制积木签名由按顺序排列的固定文字和槽位类型组成，保留槽位位置，忽略参数名。字符串/数值共用一种槽位类型，布尔是另一种；只改参数名不会得到新的签名。

## 事件与控制流

事件写在文件顶层时属于舞台，写在 `@sprite` 创建或追加体中时属于该角色。第三方事件写成 `命名空间.帽子文本 { ... }`，归属规则相同。

```scratch
@sprite "事件示例" {
    @init {}
    当绿旗被点击 {
        [将 $score 设为 0]
        [说 "游戏开始！" 2 秒]
    }

    当角色被点击 {
        [将 $score 增加 1]
    }

    当按下 /'space'/ 键 {
        [广播 "跳跃"]
    }

    当收到广播 "跳跃" {
        [将 y 坐标增加 50]
    }
}
```

解析事件时先识别完整的 `帽子头 { 脚本体 }`，根据所处位置选择事件帽子模板，不能只看前缀后的第一个字符。帽子模板可以以槽位开头，例如 `ext.(x 坐标) 达标 { ... }`；这里的 `(x 坐标)` 可以是帽子的第一个参数。脚本体的 `{` 必须位于字符串、菜单和嵌套积木之外。显式 `.hat(...)` 调用直接选择帽子模板。

以下控制流写在事件或自制积木内部，不能单独放在文件顶层。编译器支持这些内置控制流，尚不支持第三方扩展的 C 型积木。

```scratch
重复执行 10 次 {
    [移动 10 步]
}
重复执行 $count 次 {
    [右转 15 度]
}

重复执行 {
    [移动 5 步]
    [碰到边缘就反弹]
}

重复执行直到 <$hp < 1> {
    [等待 1 秒]
}

如果 <碰到 /'边缘'/ ?> 那么 {
    [说 "撞墙了！"]
}

如果 <$score > 100> 那么 {
    [说 "通关！"]
} 否则 {
    [说 "继续努力"]
}
```

计次循环对应 `control_repeat`，无限循环对应 `control_forever`，条件循环对应 `control_repeat_until`，两种条件分支对应 `control_if` 和 `control_if_else`。`循环 N 次 { ... }` 是 `重复执行 N 次 { ... }` 的别名。
