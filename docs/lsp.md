# 语言服务器

语言服务器与 CLI 共用一个可执行文件，启动命令是 `sbdsl lsp --stdio`。Rust 实现放在 [`compiler/src/lsp/`](../compiler/src/lsp/)，VS Code 客户端放在 [`vscode/`](../vscode/)。插件安装和设置见 [VS Code](./vscode.md)。

## 通信与文本同步

[`mod.rs`](../compiler/src/lsp/mod.rs) 使用 `lsp-server` 收发 stdio 消息。标准输出只写 JSON-RPC 协议帧，日志写标准错误。初始化时声明 UTF-16 位置编码、打开与关闭通知、全文变更同步、保存通知和补全。

客户端用 `vscode-languageclient` 启动 `server/sbdsl.exe lsp --stdio`，可执行文件使用绝对路径。构建和检查也使用同一个选定的编译器；启动参数以数组传入，`shell: false`。

同步的文档包括本地 `.sbdsl`、语言模式为 ScratchDSL 的未命名文档，以及任意名称的构建配置 `*.buildsb`。配置使用独立的 `sbdsl-build` 语言模式；仅打开配置也会启动语言服务。文件监听覆盖源码、构建配置和 `.js`，磁盘文件改变后重新分析。

## 未保存文件与工程入口

[`SourceProvider`](../compiler/src/analysis/source.rs) 统一处理文件读取、存在检查和路径身份。打开文件的文本覆盖磁盘内容，因此已经有文件路径、尚未保存的新模块也能被其他模块导入。关闭文件后重新使用磁盘内容。

分析配置文档时，精确使用当前 `*.buildsb` 的 `entry`；分析源码时，才向上寻找最近的默认配置 `sbdsl.buildsb`。因此任意命名的配置可以直接打开或显式选择，自动发现则只识别默认名称。打开一个导入模块不会把它变成新入口。未保存的配置也参与查找和解析；配置有误就报告配置错误，不继续使用旧值。找不到配置时，当前源码就是入口。插件的构建与检查遵循相同的选择规则，构建按钮精确选择其所在编辑器的配置，执行前先保存相关文件。CLI 直接指定源码时则可以覆盖配置入口，见 [CLI](./cli.md)。

未命名文档没有本地路径，只做局部语法检查和补全，不能解析相对导入。

## 诊断

文本变更后等待约 150 毫秒，再把文档快照交给后台线程。协议主循环继续处理补全请求。每个任务带有工程修订号；结果返回时若修订号已经改变，就丢弃该结果。错误修复、重新分析和文档关闭后，会清除不再适用的诊断。

解析器与 Binder 保存 UTF-8 字节范围，[`text.rs`](../compiler/src/lsp/text.rs) 将它转换为 LSP 的 UTF-16 行、字符位置，并处理文件 URI。诊断直接使用这些位置，不从 CLI 错误文本中截取行号。

共享分析把入口及其导入模块解析成 AST，再按声明顺序合并角色、数据和自制积木，执行作用域绑定与积木检查。同一份文档快照中，每个工程只分析一次；导入模块即使没有在编辑器中打开，也会收到诊断。一个模块有错不会阻止其他模块继续分析。打开但未被入口导入的文件单独检查语法，不把它的声明混入工程。

解析器在声明、语句和缩进边界恢复，保留能够识别的 AST 节点，并收集多条语法错误。模块合并和 Binder 也会继续检查独立节点，因此语法错误、缺失导入、重复定义、列表与参数引用、模板匹配和目标限制可以一起显示。条件或事件头有错时，仍检查能够解析的脚本体。CLI 构建继续使用严格解析和绑定，不会把恢复出的不完整 AST 当成可编译程序。

诊断不生成积木图，也不解码造型或音频。完整资源检查仍由 `sbdsl check` 和 `sbdsl build` 完成。破损到无法确定边界的片段会被跳过，部分错误仍标记整个积木；`sbdsl.buildsb` 的配置解析仍先报告一个错误。暂未实现跨快照的增量依赖图或入口选择器。

## 补全

[`completion.rs`](../compiler/src/lsp/completion.rs) 从 Rust `Registry` 读取模板、积木形状、槽位默认值、菜单和扩展命名空间，生成带参数占位符的 snippet。它用局部词法扫描处理 `移` 这类尚未写完的输入，不要求整份源码先通过解析。

赋值语句使用 `score = 10`、`score += 1`、`logs = {}` 等形式。脚本行首和赋值左侧补全可见变量与列表，右侧补全普通值和算术表达式；`global:` 用于全局数据。列表槽位的圆括号内只补全列表，其余值槽位只补全变量等普通值。变量设置与增加模板生成独立赋值片段，不加命令方括号，也不再提供旧中文赋值命令。

构建配置与 `init` 共用数据上下文扫描，按当前对象提供属性和布尔值补全，并为 `init` 的旋转方式提供枚举候选；配置中的 `runtime`、`stage` 与资源对象也会切换到各自的字段集合。新字段默认使用裸键，识别换行分隔和 `#` 注释；这部分不提供资源路径补全。

[`symbols.rs`](../compiler/src/lsp/symbols.rs) 收集变量、列表、自制积木和当前过程参数。每次请求使用当前文档及打开文件的文本，按最近配置的入口展开导入，不依赖上一次诊断结果。定义和赋值扫描允许积木或脚本尚未写完；它只用于补全，不改变编译器的语法检查。未命名文档只收集自身定义，不执行扩展 JavaScript。

符号候选遵循全局、角色私有及公共过程的词法作用域，同签名私有过程遮蔽公共过程。数据来自初值与脚本赋值，不从正在输入的孤立引用推断种类。在积木输入括号、算术表达式和 `loop` 次数位置，可以输入名称或手动唤起变量补全；`:`、`@` 和算术运算符等字符也可以触发补全。引用的替换范围包含已有名称后缀；变量和列表名称只允许普通标识符，带引号的过程参数名称仍使用 DSL 转义。自制积木候选会与内置模板一起校验匹配结果，避免补全成另一个同文积木。

扩展 C 型积木的补全会按元信息插入冒号、缩进体及后续 `else:` 分支；显示文字有歧义时使用显式 opcode。分支数错误和各分支体内的错误均参与实时诊断。

能够确定所在目标时，补全会过滤仅适用于舞台或角色的候选。替换范围会考虑已有的闭合括号、中文与 emoji，片段中的特殊字符按 snippet 规则转义。

字符串、注释和菜单内容中不显示积木候选；已经输入参数后，也不会用补全重写整条调用。扩展中同文模板存在歧义时，候选使用显式 opcode 语法。仍有歧义的内置候选会被略过。补全过程不执行动态菜单方法。

可用功能和暂未支持的操作见 [VS Code 插件说明](vscode.md#目前的限制)。服务器只声明已经实现的能力。

## 扩展缓存与工作区信任

扩展只从本地路径读取，嵌入式 JS 引擎用于提取元信息。缓存以有序的配置路径和文件内容区分扩展集合，同时保存验证通过的 `Registry` 和提取失败的结果。普通源码编辑不会重复执行扩展 JS；扩展文件保存修改后才重新提取。

客户端通过初始化选项 `allowExtensions` 传入工作区信任状态。受限模式不执行工程扩展：没有配置扩展时，照常检查内置语义；配置了扩展却未加载模板时，跳过依赖模板的绑定，避免把缺失模板误报成源码错误。授予信任后客户端重启服务器；撤销信任由 VS Code 重载窗口处理。

受限模式同时禁用构建和检查命令，并忽略工作区级的 `scratchdsl.serverPath`。默认服务器来自插件包，定位时不搜索 PATH。

## 高亮与测试

高亮由 TextMate 语法处理，独立于 LSP。积木固定文字、声明名称、过程模板、参数、角色、模块和扩展分别使用对应的标准 scope，由编辑器主题配色。它区分 `#` 的行注释、同行闭合注释和独占行块注释，也区分菜单与除法 `/`、比较运算符与布尔括号。`init` 与构建配置使用数据上下文，识别裸字段名、JSON 字面量和 `#` 注释。

共享分析测试和 stdio 进程测试覆盖 AST 恢复、多文件多错误、未打开模块的诊断与清除、未保存文本、配置入口、文档版本、URI、关闭后的磁盘恢复及退出流程。插件另有 TextMate 测试和隔离的 extension-host 测试。运行命令见[开发与打包](./development.md)。

协议实现可对照 [VS Code 语言服务器指南](https://code.visualstudio.com/api/language-extensions/language-server-extension-guide)与 [`lsp-server`](https://docs.rs/lsp-server/latest/lsp_server/)。
